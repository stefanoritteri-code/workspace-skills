# Claude's own tools — what this room uses before anything of ours

Claude already gives the owner buttons for choices, docs, designs, scheduled tasks and files. Use Claude's own tool for the work; the door stays the record, and only what the record needs goes through it. Every gate in the room instruction and in the skill still holds exactly as written: nothing filed without the owner's yes, no draft sent, every receipt read back as it is. A button press, a doc or a design never stands in for a yes the skill asks for.

Whether a tool is here is measured, never assumed: it is here when Claude offers it in this conversation, and it is not when the attempt is refused or the tool is absent. When one is missing, keep the work in the chat and say why in one line, in the owner's language, then carry on. Never say a doc, design or task exists until Claude's own tool has returned it, with its link where it has one.

## Question buttons — every choice the owner makes

Put each choice as Claude's own question buttons: options to tap, several picks, or a ranking. Two to four options, each a few words in the owner's language, the recommended one first; the owner can always answer in their own words instead. Works on every plan, on the computer and the phone.
Without them (for instance in a run nobody is watching): the same choices as one numbered line, answered in words. «Scegli: 1 … 2 … 3 …» / “Choose: 1 … 2 … 3 …”.

## Claude docs — any text worked on over days

A brief, an issue, a blueprint, the week's reading, a verdict: write it as a Claude doc the owner can edit, tick, comment on and export (Word, PDF, Markdown, Google Docs). Give the owner its link, and keep revising the same doc rather than making a new one each round. Paid plans only (Pro, Max, Team, Enterprise; on Enterprise once an admin turns docs on). Editing is on the computer; the phone opens a doc to read.
Without docs: the text stays in this chat, and one line says why — «I documenti di Claude richiedono un piano a pagamento e qui non ci sono: il testo resta in questa chat.» / “Claude docs need a paid plan and are not here, so the text stays in this chat.”

**Filing a doc on the record.** The door cannot read a doc and has no act that files a link as a link. When the owner wants the doc kept on the record, offer it in one line, and on their yes use `write_page` with `author: counterpart`: a short page titled for the doc, holding its title, its link and its date, and nothing of its text. Follow the skill's own landing rules for the title and path. When the owner names the project, then `file_page_under_project` with the page from the receipt and their words. Read the receipts back as they are.

## Claude Design — layouts

Post layouts, carousels, one-pagers, landing pages and decks, made in Claude Design in the owner's own brand system once it is set up there; two or three options when asked. It exports PDF, PPTX, HTML and ZIP, and hands off to Canva and Adobe. It makes layouts in code, never photographs. Paid plans only. Editing is on the computer; the phone views.
Without Design: describe the layout in words in the chat — sections in order, the copy, the sizes — and say why in one line.

## Canva and Adobe — connectors the owner switches on

**Canva**: a finished design from a prompt at a platform's size, shown as a card; on every Claude plan; it spends the owner's Canva AI credits. **Adobe**: editing the owner's own photographs (background, crop, resize, light and colour adjustments); on every Claude plan; the phone runs only what was set up on the computer. Both are connectors in the owner's Claude settings, and the switch is the account's.
When one is not switched on: say which one would do it and that it is a switch in their Claude connectors, then do what can be done here.

**No new photographs from a prompt.** Claude cannot make a photograph, or a photo-real or painted picture, from a description, and none of these tools does it here. Say so plainly when asked, and offer what exists: a layout, a Canva design, editing a photograph the owner has, or a drawing made in code — a diagram, an icon, a simple vector illustration — which Claude and Claude Design can make.

## Scheduled tasks — work that arrives by itself

A task the owner sets once that runs on its own: hourly, daily, on weekdays, weekly or by hand, with the computer off, and a notification on the phone when it is done. Pro plans and above. The owner makes it, either in this project's scheduled tasks or by asking for one in a conversation here, where Claude sets it up after its own questions; a skill writes the request and offers it, and never sets one up unasked. The owner chooses the cadence, the day and time, and the request it runs, which we write for them to approve. The first run asks whether to allow the door's read tools for all scheduled runs; allow the read tools only. That choice is reported not to stay every time, so a run can still stop at a read and wait to be opened. Leave writes asking for approval. A scheduled run does what the skill allows and nothing more: a write, and anything that needs the owner's yes, waits for them to open the run and answer, and nothing is said to be filed before its receipt is read. What happens to a question nobody answers is not documented, so never count on a run having filed anything.
Without scheduled tasks: offer the same request as a line the owner says when they want it.

## Files — spreadsheets, documents, slides

A sheet, a Word file or a deck the owner downloads, made with Claude's own file tools; it opens on every surface. A file is a copy at the moment it was made, so say its date, and say what it was made from.
Without file making here: the table stays in the chat, ready to copy.
