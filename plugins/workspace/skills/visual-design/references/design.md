# Design and websites

Work from brief → structure → direction → prototype → review, starting at the actual stage and preserving adopted choices. Retrieve relevant rules and examples, then [visual-controls.md](visual-controls.md) for the existing identity, preserve/overhaul choice, assets and visual controls.

Clarify deliverable only where missing: structure, visual board, clickable prototype, editable files or publication. State actual route and proof. Supplied text/images allow a specification; an identified editor connector allows only exposed operations; a viewable PDF does not promise editing its complex original. If execution is unavailable here, say so once; prepare design and a precise handoff; if Week is held, offer once to record it as a change request. The door is no terminal, browser or host.

Define recipient, need, message, main action, content, formats/languages, constraints, date and future maintainer. A site needs essential pages/functions; print needs actual supplier format/bleed/profile requirements. Invent no biography, statistic, testimonial, service or mandatory copy. State reversible assumptions; ask for a missing choice that changes structure. End the brief with an observable success criterion.

Map entry → understanding → evidence → action → outcome. Give each page its purpose, section order and known/missing content. Use comprehensible labels and heading hierarchy. Start with a representative undecorated structure. Graphic work uses the same reading order, grid, image/text relation, margins and adaptation. Narrow corrections need no whole-site remake. Mark demonstration buttons/forms and missing integration; define loading, empty, error, success, validation and return states for real interactions.

Translate actual references into grid, typographic hierarchy, reasoned palette, image treatment and small-screen behavior. A meaningful sample might show header plus content, cover plus inside page, or composition plus adaptation. Explain where the eye goes first. A second direction must represent a real difference.

Build through a verified route, preserving originals and versioning work. Reuse coherent components/styles, separate content where maintainability benefits, and consider small/large screens, long text and missing images from the start. Do not invent dependencies or commands for an unread codebase. Written code remains unexecuted until a real executor runs it; a static render is not a working website and a fake success screen does not prove saved data.

Reopen the actual result. For websites check primary flow, links, navigation, real forms/states, text, mobile/desktop layout, contrast, keyboard movement, visible focus and relevant image descriptions. Run real browser checks through a capable connector or have the executor return evidence; screenshots alone cannot certify performance, accessibility or behavior. For graphics inspect final-size hierarchy, crops, margins, resolution, fonts and export against actual supplier requirements. Fix demonstrated defects, then recheck affected behavior. A missing preview remains an unperformed visual review.

Return result/version, actual editable format, inspected preview, completed checks and limits. Distinguish prepared, modified, executed, verified and published. Publication is a distinct authorized operation through the actual route, not implicit in layout approval.

File a Design page via [landing.md](landing.md), with brief, structure, chosen direction, actual result, review and exact corrections; link the adopted owner decision and dated follow-up only if chosen. Resume from canonical page and live rules; the record never silently updates editor files.
